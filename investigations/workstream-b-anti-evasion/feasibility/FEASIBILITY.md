## 2. What was tested

### 2.1 The one candidate

| Stage | Rule | Mechanism (existing capabilities only) |
|---|---|---|
| **Detection** | Unchanged S0: churn set (600 s, cap 3, N-1 WATCH 1800 s), fingerprint dilution (600 s, cap 6), IPv6 macro scopes, Current/Previous bridges, ephemeral overflow. Still observed at every command, so a `checkOnly`, a success and a failure all keep feeding S0's state | `addDistinctBounded[AcrossRotation]`, `incrementWatchFlag` — as S0 |
| **Qualified abuse** | A trigger is *enforced* only if the **same scope** was re-corroborated by the S0 threshold using members of **scored** commands in a fixed 60 s window. Scored = a reported failure (`recordFailure`), or any outcome of a policy with access scoring (API_OVERUSE and custom API). `checkOnly` and a success of an auth policy never corroborate. One fingerprint repeated N times is one member | per scope: a 60 s bounded distinct set (the existing private `addBoundedCorrelation`, cap 3 / 6, rotation-aware); reaching the cap writes one fixed-60 s WATCH marker (`incrementWatchFlag`) read (`getWatchFlag`, current then previous generation) only when an S0 trigger fires |
| **Enforcement key** | Unchanged: K2 for churn/macro, K3 for MEDIUM/HIGH dilution (after the existing two-window confirmation). Scope-safety comes from *when* the key is enforced, not from a narrower key: no narrower key exists that an attacker cannot rotate for free (K3/K5 are fresh per fingerprint), and K4 is **not** created from device churn | — |
| **Scope-safe recovery** | The window is fixed from its first write (never refreshed) and ends at or before the 60 s block it caused; a re-block needs **new** corroboration. Old 600 s history alone can never re-issue a block | fixed-TTL sets/WATCH (`CorrelationStoreInterface`: must not refresh the TTL) |
| **LOW cross-IP** | **PSC**: dilution is corroborated like every other scope (6 distinct failing/scored K1 members in 60 s). **PSC-A** (same patch, one switch): LOW dilution is advisory (no state, no enforcement) | — |

* The patch ([`patches/psc-candidate.patch`](patches/psc-candidate.patch), sha-256 pinned in `build_candidate.sh`) adds 80 lines, removes none and touches one file; only `private` members are added; the direct store calls are `incrementWatchFlag` and `getWatchFlag` only (`expected/store_calls.txt`); a minimal custom store with **no** snapshot capability runs it (F04 C1).

## 4. Why the separation is not obtainable (G16, G17)

1. **A06 re-run unchanged:** four attacker/legitimate pairs carry byte-identical `(t, ip, UA, fingerprint, account, outcome)` streams and are treated identically by S0, EQL, EQV, PSC and PSC-A. The `I2` pair (password-expiry failure wave of LOW users vs a distributed LOW guesser) is exactly the X2/X7-vs-D1 trade; `I1` (cookie-clearing colleagues mistyping vs a fingerprint-rotating insider) is exactly the D2/API-vs-Y7 trade.

Reading: the cap at which the legitimate collateral vanishes (API 4, LOW 12) is exactly where the attacker with the *lower rate* (Y7: 3 distinct fingerprints cycled; X7: one failing IP per 15 s, i.e. 4/min < the 4.8 typos/min of D1) falls back to the no-correlation control. ## 6. Residual risks and what is not proven

* Streams are synthetic and small (≤ 600 users, ≤ 40 minutes); D1/D3/D4-class population effects are the only scale cases. Percentages describe these streams, not production traffic. "Retained %" and the `PRESERVED/PARTIAL/LOST` labels are reporting conventions (tolerance = 10 % of S0's benefit), not security thresholds.
* The public result exposes no winning `source`; the decision scope is derived from persisted enforcement plus a counterfactual control run (`lib/fsb.php`). Score-only soft decisions without a persisted block appear as `none`.
* Previous-generation **marker** read is not exercised by any assertion: a K2 block and its marker end together, so only dilution/macro scopes could need it; it is identical code to PR #105's read. Declared UNPROVEN beyond code symmetry. Macro-scope window state starts only after the S0 adaptive scope activates (Y9a/Y9b show the resulting extra verifications: 12/31, 8/12).
* Redis time cannot be controlled: exact boundaries are claimed only on the controlled clock; Redis has immediate sequences, 8-worker × 12-round concurrency (a correctness probe, not a stress test), one live 63 s check and a real outage. `REDIS_SPOTCHECK=0`/`FSB_REDIS_LIVE=0` make those gates `UNPROVEN`.
* The corroboration rate is a *rate* statement: an attacker slower than `cap` distinct fresh members per 60 s (e.g. one failure per 30 s) is not corroborated, exactly like a legitimate insider/typo rate below it. That is the A06 ambiguity expressed as a rate, not a defect to be tuned away.
* Poisoning is not removed: an insider needs ≥ 3 distinct failing fingerprints per minute (F07: 72–102 of 120 legitimate requests denied at 3–12/min), vs 1 failure for EQL and none for S0. K1 spray collateral (D2: 108/121 in **every** variant, #106) is a separate, untouched mechanism.
* Trusted sessions (`isSessionTrusted`) were not exercised: the shared streams carry none; their interaction with window membership is UNPROVEN.

Runtime ≈ 10 minutes (two 63 s live-recovery waits). Redis safety (inherited from #103 F103-01 and #104/#105): `run.sh` starts its **own** loopback instances (`--bind 127.0.0.1 --protected-mode yes`, no persistence) on free ports from `REDIS_PORT` (default 6399), proves with a decoy server holding a sentinel key that foreign / mismatched-pid / mismatched-dir / non-empty servers are refused (rc 3,3,3,3, sentinel intact), ignores `REDIS_HOST`/`REDIS_PORT`, never issues FLUSH*/CONFIG SET/DEBUG/SHUTDOWN, uses its own namespaces. The only process the scenarios terminate is the instance they have just proven to be the one `run.sh` started (R7 outage).
Self-tests that must **detect** a mutation or the run fails: remove the corroboration (`ungated`), lengthen the window to the 600 s horizon, remove correlation from S0, move the DEC-003 boundary; four provenance refusals; four build-recipe refusals (wrong baseline hash 3, absent patch 5, modified patch 6, patched-hash mismatch 7); twelve fail-closed report cases.
